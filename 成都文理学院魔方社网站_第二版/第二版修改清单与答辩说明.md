## 二、技术取舍说明

1. **为什么不用 Three.js**：需求优先原生 HTML/CSS/JS；CSS 3D transform 足以渲染
   27 个立方块，且零依赖、离线可用、文件体积小，答辩时每行代码都能讲清楚。
2. **为什么不用第三方魔方模拟器 / iframe**：外链依赖不稳定、不可控、难自定义样式；
   自研约 300 行代码即可覆盖全部交互需求。
3. **移除 Google Fonts**：境内访问 Google Fonts 不稳定且阻塞加载，改为系统字体栈
   （Noto Sans SC / 苹方 / 微软雅黑按序回退），无视觉损失。
4. **图片处理**：校徽 PNG 原图 800×800 白底 → 白色转透明 + 缩放 512px（约 100KB）；
   社徽 JPG 1024×1024 白底 → 同样处理；海报 5461×8192 / 6.5MB → 等比缩放 1600×2400
   + JPEG 质量 84（742KB），二维码与文字经截图验证清晰可读。

## 三、核心技术点（答辩讲解提纲）

### 1. 3D 魔方的"结构"
- 每个 `div.cubie` 定位在舞台中心，包含 6 个 `<i>` 面；
- 六个面用固定 transform 摆位：例如右面 `rotateY(90deg) translateZ(边长/2)`；
- 建魔方时按小方块坐标 `(x,y,z)` 判断哪些面露在外面（点积 = 1），露出的面贴色。

### 2. 魔方的"状态"
- 位置 `p = [x,y,z]`（-1/0/1），姿态 `m` = 3×3 整数矩阵；
- 渲染：`transform = matrix3d(...)`，把 p 变成平移、m 变成旋转（列主序拼装）。

### 3. 单层转动
- 绕某轴转 90° 的整数矩阵 `R`；该层 9 块执行 `p ← R·p`，`m ← R·m`；
- 纯整数运算 → 永远精确、不会漂移；
- 动画：先加 CSS `transition`，再写新 `matrix3d`，浏览器自动插值。

### 4. 手势 → 转动 的映射（本项目最"数学"的部分）
- 拖动方向从屏幕坐标逆变换回魔方坐标系（乘舞台旋转的逆矩阵）；
- 旋转轴 `ω = 面法向 n × 拖动方向 d`（叉积），再吸附到最近的 x/y/z 轴；
- 要转的层 = 被点小方块在该轴上的坐标。

### 5. 视角与自动旋转
- 所有方块外套 `#cubeStage`，`rotateX(rx) rotateY(ry)`；
- `requestAnimationFrame` 每帧 `ry += 0.12°`；用户操作后暂停 2.6 秒再恢复；
- 尊重系统"减少动态效果"设置（`prefers-reduced-motion`）。

## 四、本地预览 / 部署

- 本地：双击 `index.html` 即可；或 `python -m http.server 8080`。
- 部署：纯静态，把 `index.html + css/ + js/ + assets/` 上传任意静态空间即可。
- 注意：csTimer 计时器是 iframe 外链，需要联网；其余功能完全离线可用。
